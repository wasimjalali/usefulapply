Branch: `fix/engine-audit-sol`

## Finding resolutions

1. **Critical: cache-miss client facts**: Removed `cachedContextData` from the request contract and client payload, and cache misses now rerun from the authenticated session job description plus server-owned CV documents (`src/app/api/agent-v2/route.ts:479`, `src/app/api/agent-v2/route.ts:815`, `src/components/chat/useAgentWorkflow.ts:980`).
2. **Critical: JD wording treated as candidate facts**: Skill matching now returns literal source-CV evidence with claimability tiers, and generated-document prompts receive only candidate-side evidence rather than JD wording (`src/lib/agents/context-builder.ts:324`, `src/lib/agents/context-builder.ts:527`, `src/lib/agents/prompts/cv-prompt.ts:26`).
3. **Critical: client CV section treated as evidence**: Section regeneration uses the server-stored generated CV for rewrite context and verifies new claims only against server-owned Primary CV, Master CV and literal verified metrics (`src/app/api/regenerate/route.ts:65`, `src/lib/agents/unified-writer-agent.ts:1617`).
4. **High: client email treated as follow-up facts**: Follow-up generation reads the stored application email only as wording context, while applicant facts and matching skills come from server-owned CV documents (`src/app/api/regenerate/route.ts:65`, `src/app/api/tracker/follow-up/route.ts:60`, `src/app/api/tracker/follow-up/route.ts:383`).
5. **High: invalid applicant extraction creates false gaps**: Applicant extraction now enforces the structured shape, maps each returned value back to the exact source-CV substring case-insensitively and fails when no usable professional evidence remains (`src/lib/agents/context-builder.ts:80`, `src/lib/agents/context-builder.ts:94`, `src/lib/agents/context-builder.ts:126`).
6. **High: malformed output can be billed**: CV, fit assessment, cover letter, application email and follow-up email outputs are validated before success returns, so invalid generation throws into the existing reservation-release path (`src/lib/agents/unified-writer-agent.ts:659`, `src/lib/agents/unified-writer-agent.ts:821`, `src/lib/agents/unified-writer-agent.ts:881`, `src/lib/agents/unified-writer-agent.ts:901`).
7. **High: proficiency invented as Professional**: CV parsing preserves exact proficiency text and uses an empty string when absent instead of inventing a level (`src/app/api/parse-cv/route.ts:1057`, `src/app/api/parse-cv/route.ts:1134`, `src/lib/types/cv-schema.ts:119`).
8. **High: employer text routed through Channel A**: Removed the employer-text instruction channel from cover-letter and email prompts; only the authenticated, capped `userInstruction` block can express applicant intent (`src/app/api/regenerate/route.ts:85`, `src/lib/agents/prompts/cover-letter-prompt.ts:77`, `src/lib/agents/prompts/email-prompts.ts:187`).

## Review fixes

The adversarial follow-up identified 22 regressions in the first audit patch. All 22 are fixed.

### Critical

1. **C1, optional CV output fields:** Optional string fields now accept omitted, null and empty model values. Required validation is limited to fields the templates need, while absent optional values are normalized.
2. **C2, early-career CVs:** Empty experience is accepted when education, skills or projects provide meaningful content. Experience dates, bullets and generated IDs are optional.
3. **C3, ordinary PDF extraction:** Source membership now normalizes Unicode and whitespace on both sides. Invalid array entries and unsupported claims are dropped individually with warnings, null arrays become empty and extraction fails only when no professional evidence survives.
4. **C4, anonymous cache misses:** Anonymous continuations with an expired context return the clean context-expired response without dereferencing an absent user.
5. **C5, current job description:** Full generation and cache-miss recovery prefer the submitted job description and use the stored session value only as a fallback. Changed descriptions are persisted for stored sessions.

### High

1. **H1, unsafe substring membership:** CV evidence and missing-skill checks use Unicode-aware whole-term matching after NFKC and whitespace normalization. Short names such as Go, AI and Java no longer collide with larger words.
2. **H2, normal email output recovery:** Name checks are case-insensitive and whitespace-normalized, numeric delay strings are accepted and a follow-up failure no longer discards a completed application kit. The client clears a stale follow-up when none is returned.
3. **H3, style validation recovery:** Fit output is pinned to literal English headings with a 200-word cap. Cover letters allow header overhead, blacklist matches require boundaries and one corrective retry runs before validation can fail the kit.
4. **H4, fit-score sanity ratio:** Match details record whether each requirement is required. The sanity numerator now counts matched required requirements only.
5. **H5, split match semantics:** Match output now carries employer-side `matchedRequirements` for counts, chips and session persistence plus source-CV `claimableEvidence` for writer allow-lists. Email evidence is outside the untrusted employer block.
6. **H6, regenerated language and certification evidence:** Regeneration validates constructed language and certification strings by their source-backed components, including arbitrary multiword proficiency labels.
7. **H7, local fit cache recovery:** Signed-in local-only sessions recover an expired fit context from server-held CV documents and the submitted job description, then reserve the normal continuation price. Anonymous and source-less cases keep the clean expired-context response.
8. **H8, first-upload ordering:** The signed-in CV document save completes successfully before the parsed CV advances the queued fit flow.

### Medium

1. **M1, verified metric filtering:** Regeneration keeps structured summaries, structured bullets and bullet-like source lines only when they contain achievement-shaped quantities. URLs, emails, phone numbers, date ranges and postcode lines are excluded, results are deduplicated and capped at 30.
2. **M2, language classification:** Short model replies can contain a supported code token, classifier input is sanitized and the reasoning budget is 2,048 tokens. English fallbacks are reported through server error tracking. Detected language is persisted, reused and classified in parallel during full and fit orchestration.
3. **M3, sparse job descriptions:** Missing or null job skill and responsibility arrays normalize to empty arrays.
4. **M4, matcher schema consistency:** The unused top-level `missing` output was removed. Missing requirements are derived from the tiered detail records the parser consumes, and any requirement omitted by the model is conservatively synthesized as missing.
5. **M5, regenerated applicant identity:** Regeneration falls back to the stored generated CV personal block and returns a clean 400 before credit reservation if no applicant name can be resolved.
6. **M6, ATS wording policy:** CV, cover-letter and email prompts use the same rule. Job wording may be mirrored for role, domain and employer context, but applicant skill or fact wording still requires source-CV support.

### Low

1. **L1, empty language proficiency:** All six CV templates and the legacy text renderer omit the colon when proficiency is empty.
2. **L2, section rewrite isolation:** Existing section content is sanitized before it enters the rewrite prompt.
3. **L3, mixed-language parser fallback:** When model classification actually falls back to English, recognized original CV headers can supply the template language.
