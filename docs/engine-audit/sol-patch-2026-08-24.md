# Engine Audit Patch Report

Date: 2026-08-24

Branch: `fix/engine-audit-sol`

All 20 findings in `sol-report-2026-08-24.md` are fixed. The source report contains 3 critical, 7 high, 7 medium and 3 low findings. This differs from the severity split stated in the patch brief, but not from its total of 20.

## Finding resolutions

1. **Critical: cache-miss client facts**: Removed `cachedContextData` from the request contract and client payload, and cache misses now rerun from the authenticated session job description plus server-owned CV documents (`src/app/api/agent-v2/route.ts:479`, `src/app/api/agent-v2/route.ts:815`, `src/components/chat/useAgentWorkflow.ts:980`).
2. **Critical: JD wording treated as candidate facts**: Skill matching now returns literal source-CV evidence with claimability tiers, and generated-document prompts receive only candidate-side evidence rather than JD wording (`src/lib/agents/context-builder.ts:324`, `src/lib/agents/context-builder.ts:527`, `src/lib/agents/prompts/cv-prompt.ts:26`).
3. **Critical: client CV section treated as evidence**: Section regeneration uses the server-stored generated CV for rewrite context and verifies new claims only against server-owned Primary CV, Master CV and literal verified metrics (`src/app/api/regenerate/route.ts:65`, `src/lib/agents/unified-writer-agent.ts:1617`).
4. **High: client email treated as follow-up facts**: Follow-up generation reads the stored application email only as wording context, while applicant facts and matching skills come from server-owned CV documents (`src/app/api/regenerate/route.ts:65`, `src/app/api/tracker/follow-up/route.ts:60`, `src/app/api/tracker/follow-up/route.ts:383`).
5. **High: invalid applicant extraction creates false gaps**: Applicant extraction now enforces the structured shape, maps each returned value back to the exact source-CV substring case-insensitively and fails when no usable professional evidence remains (`src/lib/agents/context-builder.ts:80`, `src/lib/agents/context-builder.ts:94`, `src/lib/agents/context-builder.ts:126`).
6. **High: malformed output can be billed**: CV, fit assessment, cover letter, application email and follow-up email outputs are validated before success returns, so invalid generation throws into the existing reservation-release path (`src/lib/agents/unified-writer-agent.ts:659`, `src/lib/agents/unified-writer-agent.ts:821`, `src/lib/agents/unified-writer-agent.ts:881`, `src/lib/agents/unified-writer-agent.ts:901`).
7. **High: proficiency invented as Professional**: CV parsing preserves exact proficiency text and uses an empty string when absent instead of inventing a level (`src/app/api/parse-cv/route.ts:1057`, `src/app/api/parse-cv/route.ts:1134`, `src/lib/types/cv-schema.ts:119`).
8. **High: employer text routed through Channel A**: Removed the employer-text instruction channel from cover-letter and email prompts; only the authenticated, capped `userInstruction` block can express applicant intent (`src/app/api/regenerate/route.ts:85`, `src/lib/agents/prompts/cover-letter-prompt.ts:77`, `src/lib/agents/prompts/email-prompts.ts:187`).
9. **High: CV authoritative language missing**: Full and section CV generation now receive an explicit allow-listed output language and must preserve source-CV proficiency qualifiers exactly (`src/lib/agents/prompts/cv-prompt.ts:118`, `src/lib/agents/prompts/cv-prompt.ts:210`, `src/lib/agents/prompts/cv-prompt.ts:747`).
10. **High: PDF and DOCX header language misdetected**: The document parser now returns an allow-listed `documentLanguage`, with shared Workers AI classification over the full extracted body as fallback (`src/app/api/parse-cv/route.ts:342`, `src/app/api/parse-cv/route.ts:719`, `src/lib/utils/language-detector.ts:45`).
11. **Medium: sparse original headers replace localized headers**: Parsed or extracted original headers now overlay a complete localized header set instead of replacing it (`src/app/api/parse-cv/route.ts:349`, `src/app/api/parse-cv/route.ts:351`, `src/app/api/parse-cv/route.ts:358`).
12. **Medium: language thresholds differ across paths**: All generation and parsing paths now use one shared `@cf/openai/gpt-oss-120b` Workers AI classifier with an exact seven-code allow list and an English fail-safe (`src/lib/utils/language-detector.ts:12`, `src/lib/utils/language-detector.ts:31`, `src/lib/utils/language-detector.ts:45`).
13. **Medium: ad text is not consistently wrapped**: Raw and parsed employer text is sanitized, delimited as untrusted data and explicitly barred from changing instructions or establishing applicant facts (`src/lib/agents/context-builder.ts:230`, `src/lib/agents/context-builder.ts:235`, `src/lib/agents/prompts/fit-assessment-prompt.ts:80`).
14. **Medium: invalid full CV shape is accepted**: Structured CV output now receives field-by-field runtime validation for required personal, experience, nested-array, analysis and localization shapes before conversion (`src/lib/agents/unified-writer-agent.ts:659`, `src/lib/agents/unified-writer-agent.ts:711`, `src/lib/agents/unified-writer-agent.ts:765`).
15. **Medium: mandatory metrics contradict source availability**: Cover letters and emails use verified metrics only when available, otherwise their prompts require specific numberless achievements (`src/lib/agents/prompts/cover-letter-prompt.ts:324`, `src/lib/agents/prompts/cover-letter-prompt.ts:405`, `src/lib/agents/prompts/email-prompts.ts:271`).
16. **Medium: token accounting omissions and mislabeling**: Applicant, job and metrics usage is summed into analysis, language classification records its own generation context and matcher usage is emitted under the matching step (`src/lib/agents/unified-writer-agent.ts:1084`, `src/lib/agents/unified-writer-agent.ts:1093`, `src/lib/agents/unified-writer-agent.ts:1096`).
17. **Medium: literal Hello conflicts with localization**: Email prompts now require a localized professional greeting and validators normalize any remaining placeholder greetings before enforcing the final shape (`src/lib/agents/prompts/email-prompts.ts:120`, `src/lib/agents/unified-writer-agent.ts:871`).
18. **Low: Portuguese locale is unclear**: The seven-code contract now explicitly maps `pt` to European Portuguese `pt-PT`, and CV and email localization use that convention consistently (`src/lib/utils/language-detector.ts:4`, `src/lib/utils/language-detector.ts:16`, `src/lib/cv-parser/section-splitter.ts:400`, `src/lib/agents/prompts/email-prompts.ts:149`).
19. **Low: cover-letter address rules contradict each other**: The cover-letter rules now forbid company address lines in every language and market, including German output (`src/lib/agents/prompts/cover-letter-prompt.ts:245`, `src/lib/agents/prompts/cover-letter-prompt.ts:502`).
20. **Low: cover-letter blacklist is not enforced**: Cover-letter output validation now calls the shared blacklist and rejects matching output before it can be returned as successful (`src/lib/agents/unified-writer-agent.ts:821`, `src/lib/agents/unified-writer-agent.ts:825`, `src/lib/agents/unified-writer-agent.ts:1814`).
