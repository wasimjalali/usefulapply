# Sonnet 4.6 vs Sonnet 5.5 for the Useful Apply kit (2026-10-07)

Status: harness built, arm A not run yet. No Bedrock credentials were available to the eval, so there are no arm A numbers in this write-up.

## Question

Should the nine Claude kit tasks and CV parsing move from Sonnet 4.6 on Bedrock to Sonnet 5.5? Writing quality is the moat and grounding is mandatory, then cost and latency. Decision rule: switch all if 5.5 wins or ties on writing, fabrication is not higher, there are zero truncations, refusals or JSON failures, p95 kit latency is within +25% and cost per kit is not higher. Switch some if it wins on writing but loses on latency or on the short extraction tasks. Don't switch on any rise in fabrication.

## What ran so far

Built and verified, no model output yet:

- Dataset: 30 cases, 24 EN and 6 DE (14 owner cases on the owner CV, 16 synthetic cases on 6 constructed CVs with public ads). Details in `evals/README.md`.
- Failure modes F1 to F18 written first, then `evals/score-deterministic.ts`.
- Harness `evals/run-eval.ts`. It runs the real agent methods and prompt builders with the production request shape. It uses an eval client, not the production model module, because that module writes every call to the production D1 ledger.
- Wiring check: one case run with a deliberately invalid bearer token reached Bedrock through the real context-builder and shim and recorded four 403 failures per call, as intended. `npx tsc --noEmit` and `npx eslint evals` are clean.

Planned arm A settings: model `us.anthropic.claude-sonnet-4-6`, region us-east-1, temperature and max tokens from `MODEL_CONFIGS`, production system blocks with cache markers. Planned commands are in `evals/README.md`.

Blocker: neither `.env.local` nor `.dev.vars` defines any AWS or Anthropic variable, and `~/.aws` is off limits. Production uses Cloudflare secrets, which a script can't read. Supply `AWS_BEARER_TOKEN_BEDROCK` (or an access key pair) and re-run the three commands. Nothing else is needed.
